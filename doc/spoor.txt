1. INTRODUCTION                                                  *spoor-intro*

spoor shows the callers and callees of the function under the cursor (the
"bow-tie"), lets you walk a call path one hop at a time while keeping notes
(a "trail"), and lists the symbols changed since a git ref with their
bow-ties. Data comes from your language server's call hierarchy and from git;
where no server has call hierarchy, a same-file bow-tie comes from tree-sitter
(|spoor-syntax|). spoor has no AI, builds no index, and makes no network
requests.

==============================================================================
2. INSTALL                                                     *spoor-install*

Requires Neovim 0.11+ and git. A language server that supports
`textDocument/prepareCallHierarchy` gives cross-file bow-ties; without one,
tree-sitter gives a same-file view (|spoor-syntax|). snacks.nvim is optional:
with it pickers have previews; without it spoor uses plain windows and
|vim.ui.select()|. Tested on macOS, Linux and Windows.

With lazy.nvim / LazyVim (spoor's own `lazy.lua` brings in snacks.nvim): >lua

    return {
      "Matthew-Eucaristo/spoor.nvim",
      version = "*",
      event = "VeryLazy",
      opts = {},
    }
<
With Neovim 0.12's |vim.pack|: >lua

    vim.pack.add({
      "https://github.com/folke/snacks.nvim", -- optional: picker previews
      "https://github.com/Matthew-Eucaristo/spoor.nvim",
    })
    require("spoor").setup()
<
Any other way: put spoor (and snacks.nvim, if you want it) on
'runtimepath', run `:helptags ALL` once, and call `require("spoor").setup()`.
Without it only |:Spoor| exists.

Run |:checkhealth| `spoor` to see what each attached server supports.

3. LIVE BOW-TIE                                                   *spoor-live*

spoor stays out of the way while you move. Three ways to see the bow-tie:

K                   Your usual hover, and next to it the full bow-tie
                    (`float.depth` levels, `float.max_items` rows), in the
                    largest free part of the screen that covers neither the
                    hover nor the cursor line. Moving on closes it. Works with
                    any hover (noice, plain LSP) and with signature or
                    diagnostic floats; `live.hover = false` turns it off.

(rest)              Leave the cursor on a function for `live.card.delay` ms
                    (5000) and a small card shows the bow-tie just above the
                    cursor line. It never takes focus and goes away as soon
                    as you move. `card = { delay = false }` turns it off.

<leader>uB          Turn a panel at the bottom on or off (`live.layout =
                    "float"` puts it in a corner). It follows the cursor and
                    the choice persists across sessions. `:q` in the panel
                    pauses it for this session.

All of them look like this: >
    CALLERS 2                                       CALLEES 5
    handleOrders  server.go:32 ──╮             ╭─▶ validate
    TestProcess  order_test.go ──┤             ├─▶ applyDiscount
                                 ╰─▶ Process ──┼─▶ subtotal
                                               ├─▶ Save ◇3
                                               ╰─▶ Emit
<
On a call, the focus is the called function. Anywhere else in a body, it is
the enclosing function. Requests are debounced, stale ones are cancelled,
finished bow-ties are cached until you edit or save, and nothing is sent in
insert mode. Use |spoor-gag| to move through a bow-tie.

Bottom panel keys: <CR> jump, h / l columns, <Tab> open the float on the
node, t trace from the node, H show hidden, R retry, y copy as Mermaid,
q turn the panel off, g? help.

==============================================================================
4. BOW-TIE FLOAT                                    *spoor-bowtie* *spoor-gag*

gag                 Open a focused float at the cursor with `float.depth`
                    levels per side (callers of callers, callees of callees).

Moving the cursor onto a node shows its code in the code window behind the
float (`float.preview`); <Esc> or q puts that window back as it was.

Float keys: <CR> go to the node and close, <Tab> open or fold one more level
on the node, . re-root on the node, <BS> back to the previous root, t trace,
H show hidden, R retry, y copy as Mermaid, q / <Esc> close, g? help,
<C-v> / <C-s> / <C-t> keep the bow-tie open in a vertical split, a bottom
split or a new tab. There <CR> goes to the node and the split stays; q closes.

==============================================================================
5. TRACE MODE                                          *spoor-trace* *spoor-gat*

gat                 Start a trail at the cursor.
<leader>ct          Resume the last trail in this project.
<leader>cT          Pick a trail; <c-x> in the picker deletes one.

A panel opens beside the code window with the trail so far and the next hops,
numbered 1-9. Taking a hop shows that code in the code window and keeps focus
in the panel. When a hop is an interface method (◇N), you choose the
implementation; project code comes first and tests last.

Trace keys: 1-9 or <CR> take a hop (<CR> on a step shows it), <BS> step
back, n note on the step under the cursor (the newest by default), i switch
between callees and callers, <C-q> trail to quickfix, m copy as Mermaid,
q close, g? help.

Trails are saved after every change. See |spoor-files|.

==============================================================================
6. CHANGED SYMBOLS                                              *spoor-changes*

<leader>cG          List symbols changed since a ref, each with its bow-tie
                    in the preview.

The ref is `changes.base` when set. Otherwise it is the merge-base with the
default branch (origin/HEAD, main, master, trunk or develop), or HEAD when
you are on that branch. Untracked files count as new. A symbol is "new" when
its declaration line was added and its name does not appear in the old file.
New functions show their caller count, and `⚠ 0 callers` marks the ones
nothing calls.

Changed files are loaded into hidden, unlisted buffers so their language
server can answer.

==============================================================================
7. ENTRY POINTS                                                 *spoor-entries*

<leader>ce          Pick an entry point; functions start a trace.

Found with `git ls-files` and `git grep`: Go `main` and HTTP route
registrations, Next.js app and pages router files and route handlers,
package.json bin/main/scripts, Python `__main__`, route decorators and
[project.scripts], Dart `main` (→ runApp), JVM `main` and Spring mappings,
Rust `fn main`.

                                                          *spoor-entries-own*
Add your own detectors with `entries`, keyed by name. A detector is
`function(root, files)` (`files` from `git ls-files`) returning a list of
`{ name, file, lnum, col?, detail?, lang?, trace? }`; `file` may be relative
to `root`, `lang` defaults to the detector's name, and `trace = true` starts a
trace when picked. A built-in name (go, next, dart, python, jvm, rust, npm)
replaces that detector, and `false` turns it off: >lua

    entries = {
      make = function(root, files)
        local out = {}
        for i, line in ipairs(vim.fn.readfile(root .. "/Makefile")) do
          local target = line:match("^([%w_-]+):")
          if target then
            out[#out + 1] = { name = target, file = "Makefile", lnum = i }
          end
        end
        return out
      end,
      npm = false,
    }
<

8. EDGES, BADGES AND FRAMEWORKS                                   *spoor-edges*

Every edge is a static call reported by the language server. spoor then
reads each call site to label it:

  ◇N       the callee is an interface or abstract method with N
           implementations (textDocument/implementation)
  ~        the function is used as a value at that site (a handler,
           callback or prop), not called
  </>      JSX: rendered as a component
  ×N       N call sites
  ⚑        the focus is invoked by a framework or runtime: Go main/init/
           tests/HTTP handlers, Next.js pages/routes/actions, React
           components and hooks, Flutter build()/lifecycle, Python routes,
           tasks and tests, JVM main/Spring/JUnit

Static analysis can't see calls made through dependency-injection containers,
reflection or message buses. A function with no static callers shows
"no static callers · framework or dynamic entry?" and spoor asks for its
value references so you can see where it is registered.

                                                            *spoor-frameworks*
Add your own ⚑ rules with `frameworks`, a list of rules shaped like the
built-in ones in `lua/spoor/frameworks.lua`. Yours are tried first: >lua

    frameworks = {
      {
        id = "bun.fetch",
        label = "Bun · fetch handler",  -- shown as the caller row
        ft = { "ts", "js" },            -- file extensions; nil: every file
        only_if_empty = false,          -- only when nothing calls it
        match = function(c)
          -- c = { rel, name, kind, head, decl }: path relative to the
          -- project, symbol name and kind, the first lines of the file and
          -- the declaration (decorators through the signature)
          return c.name == "fetch" and c.head:find("Bun%.serve") ~= nil
        end,
      },
    }
<
`frameworks = false` turns the labels off. A rule that errors is skipped;
|:checkhealth| `spoor` lists the ones it can't use.

                                                                *spoor-syntax*
When no attached server supports call hierarchy (marksman, ty, or a buffer
with no server), spoor builds the bow-tie from the buffer's tree-sitter tree.
Functions and calls are found by node type name ("function", "method",
"lambda", "call", "invocation", ...), so any language with a parser works
without per-language queries. Callees are the calls inside the function;
callers are the uses of its name in the same file, grouped by the function
around each use. Callees defined elsewhere are dimmed and jump to the call
site. The bow-tie says "syntax only · this file", `.` re-roots within the
file, and |spoor-gat| needs a language server. Parsing is asynchronous and the
index is rebuilt once per edit. A server that can answer always wins;
`syntax = false` turns the fallback off.

10. CONFIGURATION                                                *spoor-config*

Pass a table to `require("spoor").setup()` (`opts` in lazy.nvim). Defaults:
>lua
    {
      live = { panel = false, debounce = 120, layout = "bottom",
               height = 8, max_items = 6,
               card = { delay = 5000, width = 64, max_items = 4 },
               hover = true },
      float = { width = 0.86, depth = 2, max_items = 12, preview = true },
      timeout = 1500,        -- per request, ms
      cold_timeout = 15000,  -- while a server is still indexing
      max_nodes = 60,
      implementations = true,
      max_implementation_lookups = 8,
      references = true,
      syntax = true,         -- tree-sitter fallback, |spoor-syntax|
      servers = {
        dartls = { depth = 1, timeout = 20000, live_callers = false },
      },
      hide = { external = true, generated = true, tests = false },
      exclude = {},          -- Lua patterns on project-relative paths
      frameworks = true,     -- false, or your rules: |spoor-frameworks|
      entries = {},          -- your detectors: |spoor-entries-own|
      trace = { width = 58, max_hops = 9 },
      changes = { base = nil, max_files = 60 },
      keys = { bowtie = "gag", trace = "gat", resume = "<leader>ct",
               trails = "<leader>cT", entries = "<leader>ce",
               changes = "<leader>cG", toggle = "<leader>uB" },
      icons = { ... },       -- see lua/spoor/config.lua
    }
<
`servers.<name>` applies per language server: `timeout`, `depth`, and
`live_callers = false`, which makes the card and panel skip the caller search
until you press R. Set a key to false to skip it, or `keys = false` to set no
global keys.

11. HIGHLIGHTS                                               *spoor-highlights*

All groups are defined with `default = true` and link to standard groups:
SpoorHeader (Title), SpoorName (Function), SpoorFocus (bold Function),
SpoorLoc (Comment), SpoorEdge (Comment), SpoorBadge (Special),
SpoorInterface (Type), SpoorValue (Special), SpoorFramework (DiagnosticInfo),
SpoorWarn (DiagnosticWarn), SpoorMessage, SpoorMore, SpoorDim (Comment),
SpoorNote (String), SpoorKey (Special), SpoorHere (DiagnosticOk),
SpoorAdd (Added), SpoorChange (Changed).

12. LUA API AND DATA MODEL                                          *spoor-api*

require("spoor").setup({opts})       Configure and map keys.
require("spoor").bowtie()            Open the float.
require("spoor").trace()             Trace from the cursor.
require("spoor").resume()            Resume the last trail.
require("spoor").trails()            Trail picker.
require("spoor").entries()           Entry-point picker.
require("spoor").changes({ref})      Changed-symbols picker.
require("spoor").toggle({on})        Live on/off; nil toggles.
require("spoor").current_graph()     Current bow-tie as JSON-ready data.
require("spoor").current_trail()     Current trail as JSON-ready data.

Graph: `{ version, focus, server, source, nodes = { { id, name, kind, path,`
`range, selection, tags, impls?, framework? } }, edges = { { from, to, kind,`
`sites, source } } }`. `source` is "lsp" or "syntax" (|spoor-syntax|). Edge
kinds: "call", "jsx", "ref". Ids look like
"internal/order/order.go#24:5" (0-based line:column), with paths relative to
the project root.

Trail: `{ version, title, created, updated, steps = { { name, kind, path,`
`line, via, note, framework } } }`.

                                                                  *SpoorTrail*
The `User SpoorTrail` autocommand fires after a trail is saved, with
`data.trail` set to the raw trail.

==============================================================================
13. FILES                                                         *spoor-files*

spoor writes only to `stdpath("state")/spoor/`:
  state.json                  whether the bottom panel is on
  trails/<project>-<hash>.json trails and notes for each project

Delete that folder to forget everything. spoor never writes to your project.
To uninstall with lazy.nvim, remove the spec, run `:Lazy clean`, and delete
that folder.
