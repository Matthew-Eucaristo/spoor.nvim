How you read code with spoor

First, pick a focus

Press K on a function: your usual hover, plus the full bow-tie next to it, two levels and every row. Move on and it goes. Rest the cursor for five seconds and a small card shows the same at a glance.

Then look at its neighbours

gag opens the bow-tie two levels deep. Moving through it shows each function's code above; <CR> goes there and <Esc> puts you back. <C-v>, <C-s> or <C-t> keep it open beside the code.

Next, follow one path

gat walks one hop at a time while the code opens beside you. Numbered next hops; on an interface you pick the implementation, and the test double is marked as one.

Last, write down what you learn

n adds a note to a step. The trail is saved as you go: resume it tomorrow with <leader>ct, send it to quickfix with <C-q>, or copy it as Mermaid with m.

Install it in one file

Restart Neovim and lazy.nvim installs spoor and snacks.nvim, which spoor's own lazy.lua declares. Open a code file and rest the cursor on a function. :checkhealth spoor shows what your language servers support.

You need

  • Neovim 0.11 or newer, and git.
  • For the full, cross-file picture, a language server with call hierarchy: gopls, vtsls, tsgo, dartls, pyright, jdtls, clangd or rust-analyzer. Without one, tree-sitter gives a same-file view.
  • Optionally snacks.nvim (LazyVim ships it) for picker previews. Without it spoor uses plain windows and vim.ui.select.
  • macOS, Linux or Windows: CI tests all three.

~/.config/nvim/lua/plugins/spoor.lua

return {
  "Matthew-Eucaristo/spoor.nvim",
  version = "*", -- follow releases; drop this line to track main
  event = "VeryLazy",
  opts = {},
}

Neovim 0.12's built-in vim.pack, in init.lua

vim.pack.add({
  "https://github.com/folke/snacks.nvim", -- optional: picker previews

Measured, not guessed

Requests are debounced (120 ms), cancelled when the cursor moves on, cached until you edit, never sent in insert mode, and capped at 1.5 s, with 15 s while a server is still indexing. dartls searches the whole workspace for callers (14–21 s on a large Flutter app), so its card and panel find callers when you press R.

Your colours

Highlight groups such as SpoorFocus, SpoorInterface and SpoorWarn link to standard groups, so spoor follows your colorscheme. Your own frameworks and entry points go in frameworks and entries.

Why a bow-tie

Field studies put about 58% of developer time into comprehension (Xia et al. 2018). Developers who succeed investigate methodically and write down what they find (Robillard et al. 2004). Focus-seeded, depth-limited views you build up yourself have better support than whole-repo graphs (Kersten & Murphy 2006, DeLine et al. 2010).

Next to what Neovim has

Neovim's vim.lsp.buf.incoming_calls() and outgoing_calls() answer one side, one hop at a time, in a quickfix list. spoor asks for both sides, two levels deep, labels interfaces, values and frameworks, and keeps the path you took with your notes.

What it never does

No AI, no index to build, no network requests, no background processes. It runs short read-only git commands and writes only to stdpath("state")/spoor/.

Questions people ask

No serverWhat if my language server has no call hierarchy?

spoor reads the buffer's tree-sitter tree instead, finding functions and calls by node type name, so any language with a parser works without per-language queries. Callers come from the server's find-references when it has one (lua_ls does), otherwise a git grep for the name. The footer says which: syntax · lua_ls references, syntax · name search, or syntax only · this file. A server that can answer always wins.

LazyVimDo I need LazyVim or snacks.nvim?

No. spoor works in plain Neovim and in LazyVim alike. With snacks.nvim, pickers show a preview and get snacks' help and toggles; without it, spoor uses plain windows and vim.ui.select, so whatever picker you registered for that is used. Icons come from mini.icons when it is installed, with plain fallbacks.

SpeedWill it slow down typing?

Three requests per bow-tie (prepare, incoming, outgoing) plus implementation lookups for interface calls, debounced, cancelled when you move on and never sent in insert mode. Rendering a 60-node bow-tie takes about 0.15 ms, so the latency is the server's. On the real projects measured in the README, gopls and tsgo answered every request within 12 ms (warm, p95).

FilesWhat does it write, and how do I remove it?

Only stdpath("state")/spoor/: state.json (whether the panel is on) and trails/, one file of trails and notes per project. To uninstall with lazy.nvim, delete lua/plugins/spoor.lua, run :Lazy clean and delete that folder.

HomebrewWhy isn't there a Homebrew formula?

Your plugin manager installs a plugin, updates it, pins it in lazy-lock.json and loads it lazily. A formula would be a second update channel LazyVim can't see, and lazy.nvim resets the runtimepath, so a plugin under Homebrew's share/nvim/site would not even load.

Building on itCan another plugin read the bow-tie?

require("spoor").current_graph() and current_trail() return plain data with project-relative paths, and User SpoorTrail fires each time a trail is saved. :Spoor graph and :Spoor trail print them as JSON.
